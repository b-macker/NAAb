# ============================================================
# flag_policy.txt -- how each src/cli/main.cpp command-line option relates to
# govern.json's policy. One decision per option, so a new option cannot land
# without someone making this call (Bundle 1 item 1.6).
#
# Read by tests/cli/test_flag_policy.sh, which compares the OPTION column
# against tools/flag_policy_coverage.py's extraction of main.cpp:
#   - an option main.cpp parses but this file lacks  -> FAIL (classify it)
#   - an option this file lists but main.cpp dropped -> FAIL (remove it)
#
# Format: option<TAB>category<TAB>one-line reason.  Categories:
#
#   bypass-guarded:<fn>  can waive or loosen governance enforcement for a run,
#                        and is DEFENDED in main.cpp by <fn> (the bypass-flag
#                        block: checkBlocked, which also honours the operator's
#                        integrity.blocked_flags, or implicitBlock for a signed
#                        project). The test greps main.cpp for <fn>, so the
#                        named defense cannot silently disappear.
#   run-policy           a run-time flag that selects, requires, or overrides a
#                        govern.json setting. govern.json is primary; a CLI
#                        override is lockable via integrity.blocked_flags. A flag
#                        may tighten govern.json, never loosen it (#341):
#                        --timeout, --memory-limit and --sandbox-level are
#                        capped by govern.json. --allow-network raises only the
#                        built-in CLI default; a govern.json network.enabled:
#                        false still removes the network (traced,
#                        syncGovernanceToSandbox). SCREENED: this is the
#                        relationship, not a proof of the enforcement direction.
#   governance-evidence  produces or annotates governance observation only
#                        (reports, SARIF/JUnit, telemetry, dashboard, lint
#                        verdict, override justification). Never loosens.
#   governance-admin     a subcommand (or its argument) that manages a
#                        governance artifact outside a governed run: authoring
#                        govern.json via init, signing, the trust store,
#                        approvals, telemetry-chain verification, attestation.
#   neutral              no govern.json setting behind it (engine default,
#                        resource/output/debug utility, fmt/scan/race/calibrate
#                        knobs, the package lockfile, help/version, and the
#                        rejected -e/-c inline-code flags).
#
# SCREENED, NOT VERIFIED (docs/investigation-method.md). The extraction is a
# search over source text; the category is a reviewer's decision about the
# relationship, not a behavioural proof of the direction of enforcement. The
# governance reload/bypass suites are where direction is tested. The guard's
# job is the CLASS: no new option reaches main.cpp without this decision.
# ============================================================
