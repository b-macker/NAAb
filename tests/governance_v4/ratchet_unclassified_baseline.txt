# govern.json keys a signed mid-run reload installs that the ratchet does NOT
# classify -- the debt tools/ratchet_coverage.py reports, pinned by
# test_ratchet_coverage.sh. Generated 2026-10-11.
#
# A key here can be changed by a reload in EITHER direction with no ratchet
# violation and no notice, wherever a check reads it live. Most are tuning
# (thresholds, weights, telemetry paths) where that may well be fine; some are
# not -- e.g. code_quality.no_temporary_code.enabled and most per-check
# `.level` keys, which a reload can switch off or lower today. Nothing here was judged; the
# list is what was left over.
#
# HOW TO CHANGE IT
#
# Removing a line is the point: classify the key in ratchet_classification.txt
# (or make the ratchet name it), with a reload test for a ratchet entry and a
# traced reason for inert/startup/neutral. The gate fails on a line that is no
# longer unclassified, so the list can only shrink.
#
# Adding a line means a NEW loader key reached the reload path unclassified.
# Do not add it here to make the gate pass: decide what a loosening of it
# means. This file existing is a record of debt, not a place to put more.
