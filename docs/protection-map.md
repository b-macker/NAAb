# Protection map: which layer stops each forbidden action

Generated by `tools/protmap/protmap.py`; pinned by
`tests/self-audit/test_protection_map.sh` against `tools/protmap/baseline.json`.
Measured 2026-10-08 on Linux (kernel 6.18), build of `0dddeaa6` plus the
shell-off executor gate (finding 1), **as root**; the env column re-measured
2026-10-09 after `blocked_read` was fed into the child-environment scrub
(finding 3). The tables below are the root measurement. Run as an ordinary
user, three cells are stronger; see finding 6.
The baseline holds both, and the suite picks the section from the effective
uid.

## Why this exists

Governance has two kinds of protection for a polyglot block:

- **Runtime**: the sandbox level, subprocess containment (rlimits, fork/exec
  gating), the executor gate, the embedded Python audit hook (paths, imports),
  and runtimes that have no such API at all (QuickJS, SQLite).
- **Text checks**: `restrictions.*`, `languages.per_language.banned_functions`,
  `capabilities.network`/`filesystem` import checks. These read the source and
  never run it.

A text check can be evaded by building the call at runtime. So a cell where the
runtime contains the action costs nothing when a text check misses. A cell
where only a text check stands is where an evasion is a real escape. A cell
where nothing stands is open even to the plain form. Fixing the comment and
string stripper one bug at a time (#294, #295, interpolation) does not say
which of these a given bug sits in. This map does.

## Method

Every verdict comes from **observing the action**, never from an exit code:

| action | the block tries to | observed by |
|---|---|---|
| exec  | start a child process (`touch <marker>`) | the marker file exists |
| read  | read `vault/secret.txt` (`vault/` is in `blocked_paths`) | a random token from that file appears in the program's output |
| write | write `vault/w.txt` | the file exists |
| net   | connect to a local TCP listener (`network.enabled: false`) | the listener accepted a connection |
| env   | read `NAAB_PM_SECRET` (in `env_vars.blocked_read`) | the variable's random token appears in the output |

The tokens are random per probe and never appear in the source, so a token in
the output can only come from performing the action. Each snippet uses the
language's ordinary API: the form a text check is written for, not an evasion.

Each probe runs three times:

1. **control**: audit mode, `unrestricted`, no policy and no rules. The action
   MUST happen here. If it doesn't, the snippet does not do what it claims and
   no verdict is drawn (UNMEASURABLE), or the runtime has no such API by design
   (NO_API, declared per runtime and still required to fail its control).
2. **runtime**: audit mode, at the column's level and policy. Audit mode turns
   every text check into a log line but keeps the sandbox, so this measures the
   runtime alone.
3. **text**: enforce mode, same column: runtime plus text checks. When enforce
   stops an action the runtime let through, the cell is called TEXT only if
   `naab-gov check` (static analysis only, never runs code) blocks the same
   code under the same config. Audit mode also silences runtime gates routed
   through `enforce()`, so this keeps such a gate from being credited to a text
   check.

Columns are a sandbox level plus a policy profile. Every column's policy
forbids all five actions, except that the `shell` profile enables
`capabilities.shell`. Subprocess languages need that to run at all, so exec is
**permitted** there and not probed.

Verdicts: **runtime**: the action is stopped while the language runs.
**refused**: the language does not run at all in this column (also
CONTAINED). **TEXT**: only a text check stops the plain form. **OPEN**:
nothing stops it. **no-api**: the runtime has no such API.

Regenerate: `python3 tools/protmap/protmap.py --md OUT.md --write-baseline tools/protmap/baseline.json`.
This writes the section for the uid it runs as. Run it once as root and once
as an ordinary user (for example `runuser -u nobody -- env HOME=/tmp/h ...`),
or CI's other job will fail PM-02. Check the non-root run's
`BASELINE ... unmeasurable here` count before writing it: `--write-baseline`
writes only measured cells, so a cell the ordinary user could not measure is
DROPPED from that section, not kept. In a container whose `/root` is mode 700
with rust under `/root/.cargo`, 32 cells read UNMEASURABLE for `nobody` even
with `PATH`, `CARGO_HOME` and `RUSTUP_HOME` passed through (observed
2026-10-09; 32 is the rust row's probed-cell count, and rust's cells were the
ones that measured once `/root` was traversable -- inferred from those two
facts, not listed cell by cell); `chmod 711 /root` for the run (and back
after) measured all 323.
The run takes about 45 s with 8 jobs and is deterministic. Five consecutive runs agreed
cell for cell, after fixing a race where Node's asynchronous connect was cut off at
program exit; see `run_probe`.

**The external commands the probes run (`touch`, `cat`, `curl`) are absolute
paths, resolved once by `tool_paths()`.** The first version called them by bare
name, which measured `PATH`, not containment: when a level denies exec, child
containment sets `PATH` to the interpreter's own directory
(`subprocess_helpers.cpp`, `restrict_path`). As root that was the only barrier,
so a bare `touch` failed to resolve and the cell read **contained** while a full
path walked straight through it — six exec cells were wrong this way. A probe
whose command cannot be found now reports UNMEASURABLE, never containment
(`probe_broken()`); `--plant-bare LANG/ACTION/COLUMN` reproduces the defect end
to end and `--selftest` checks the classifier both directions.

## What the map says

Of 323 measured cells as root: 192 contained, 67 no-api, 25 **text-only**,
39 **open** (plus 27 where the policy permits exec). As an ordinary user: 195
contained, 25 text-only, 36 open. Before finding 3's fix (2026-10-08) it was
176 contained and 55 open as root, 180 and 51 as an ordinary user: the 16 (15)
cells that moved are every subprocess language's env read with shell enabled.
Every TEXT and OPEN cell but four is in a
column where the project has **enabled** shell; the four are Python's env read
(every `deny` column) and network at `unrestricted/deny`, both TEXT-only.

1. **A project that disables shell refuses every separate-process language.**
   `capabilities.shell.enabled: false` (any form, set directly or inherited
   through `extends`) marks the sandbox `shell_disabled_by_policy`, and
   `LanguageRegistry::getExecutor()` refuses every executor whose
   `runsInProcess()` is false -- php, go, cpp, rust, shell, node, ruby, and the
   unprobed csharp/nim/julia/zig/typescript. Before this gate only the
   persistent executors (node, shell, ruby) checked for exec, so php, go, cpp
   and rust compiled and ran with shell disabled, and a plain
   `exec`/`system`/`Command` by absolute path went through: their exec cells
   were TEXT-only, and their read/write/env cells OPEN, in all three `deny`
   columns (60 cells as root, 52 as an ordinary user, all now contained). The
   gate keys on the project's decision, NOT on the level: `standard`, the
   enforce default, also withholds exec, and refusing there would refuse
   compute-only blocks in projects that never disabled shell. In-process
   runtimes (embedded Python, QuickJS, SQLite) keep running; the engine
   decides inside them. Test: `tests/security/test_shell_off_subprocess_langs.sh`.
2. **With shell enabled, `blocked_paths` reaches no subprocess language.**
   Python is held by its audit hook. php, go, cpp and rust read and write a
   blocked path in every `shell` column, and so do shell and ruby at `elevated`
   and above (at `standard` they are refused). Every one of those cells is
   **OPEN**: no text check flags a plain `os.ReadFile` / `file_get_contents` /
   `std::ifstream` of the path. Node is TEXT-only (`restrictions.imports` on
   `fs`). This is CONTRA-013: there is no OS-level path enforcement.
3. **`env_vars.blocked_read` now reaches every child process** (fixed
   2026-10-09). It used to gate NAAb's `env` stdlib only, and every polyglot
   child inherited the variable: php, go, cpp, rust, shell and ruby read it with
   nothing in the way (**OPEN**). In enforce mode the variable is now withheld
   from every child the program starts -- polyglot blocks, `process.run`, an
   `async fn`'s children, embedded Python's `os.environ` -- through the same
   child-environment scrub as `blocked_subprocess_vars`
   (`runtime::currentEnvScrubPolicy()`); audit mode leaves it alone, as it
   leaves `env.get()` alone, and operator hooks keep it. Those cells are
   credited to the runtime because the enforce run stops them and `naab-gov
   check` does not. **Python's and node's env cells still read TEXT, and that
   understates them**: their probes (`import os`, `process.env`) trip text rules
   too, and the map credits any cell a static check also blocks to the text
   check. The runtime scrub withholds the variable from both in enforce mode
   with no text rule configured -- `tests/security/test_subprocess_env_scrub.sh`
   R-python and R-node, which carry no `restrictions` block. Test for the whole
   finding: that suite.
4. **`network.enabled: false`** holds Python at runtime at `standard`/`elevated`
   only (TEXT at `unrestricted`). With shell enabled, cpp, rust and php are
   TEXT-only and go, shell and ruby are **OPEN**: go's `net.Dial` is matched by
   no check.
5. **Process spawning** is now contained wherever the project disables shell
   (finding 1). Where shell is enabled, exec is permitted by policy and not
   probed -- including at `standard`, where the level withholds exec but php,
   go, cpp and rust still start commands by absolute path (as root,
   `RLIMIT_NPROC` does not bind). That is the PATH-artifact column the
   `--plant-bare` control now uses.
6. **Running as root weakens containment** -- three cells (four before
   finding 3's fix). `RLIMIT_NPROC=0` is
   half of the fork/exec containment at `standard`, and the kernel does not
   enforce it for root. Run as an ordinary user, go is refused outright at
   `standard/shell` (its runtime cannot create threads), so its
   read/write/net cells there go from OPEN to contained; its env cell is
   contained for root too now that the child-environment scrub withholds it. Containers commonly
   run as root, so the root tables are the ones a containerised deployment gets.
7. **Contained by construction**: QuickJS (no std/os modules loaded) and SQL
   (the authorizer refuses ATTACH and VACUUM INTO) have no API for any of the
   five actions, and `restricted` refuses every subprocess language.

### What this means for the text-check work

Hardening the text checks (reading the raw text as well as the stripped text,
handling interpolation) helps only the 25 **TEXT** cells: python env (every
column) and net (`unrestricted`), node fs/net/env with shell enabled, and
php/cpp/rust net with shell enabled. It does nothing for the 39 **OPEN** cells,
which a plain call already passes, all of them in columns where the project has
enabled shell. Those need runtime enforcement inside the running language --
per-language runtime flags, a compile-time gate, or OS-level support (seccomp,
Landlock, a job object) -- or new checks with a stated limit. A project can
remove them today only by disabling shell or by not allowing those languages
(the default `naab-lang init` preset allows only python and shell; its larger
presets add go, php, rust and cpp).

## Limits

- Linux only. The containment being mapped is the POSIX implementation. The
  suite reports UNMEASURABLE elsewhere.
- Five registered runtimes have no probes: csharp, julia, nim, typescript and
  zig had no toolchain where the map was built (`tools/protmap/unprobed.txt`,
  enforced by PM-01). Their rows are unknown, not safe.
- Each action is probed in ONE ordinary form per language. TEXT means a text
  check stops *that* form. It is not evidence that other forms of the same
  action are caught.
- A probe whose external command (`touch`/`cat`/`curl`) is not installed reports
  UNMEASURABLE, not containment. If one is missing in CI the cell drops out of
  the baseline comparison rather than flipping to contained.
- The text checks are the langconform all-on rule set (`restrictions` and
  `languages.per_language` from `tools/langconform/config.json`). A project
  with fewer rules enabled has fewer TEXT cells and more OPEN ones.
