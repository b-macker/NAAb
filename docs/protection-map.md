# Protection map: which layer stops each forbidden action

Generated by `tools/protmap/protmap.py`; pinned by
`tests/self-audit/test_protection_map.sh` against `tools/protmap/baseline.json`.
Measured 2026-10-05 on Linux (kernel 6.18), build of `054ace45`, **as root**.
The tables below are the root measurement. Run as an ordinary user, nine cells
are stronger; see finding 7. The baseline holds both, and the suite picks the
section from the effective uid.

## Why this exists

Governance has two kinds of protection for a polyglot block:

- **Runtime**: the sandbox level, subprocess containment (rlimits, fork/exec
  gating), the executor gate, the embedded Python audit hook (paths, imports),
  and runtimes that have no such API at all (QuickJS, SQLite).
- **Text checks**: `restrictions.*`, `languages.per_language.banned_functions`,
  `capabilities.network`/`filesystem` import checks. These read the source and
  never run it.

A text check can be evaded by building the call at runtime. So a cell where the
runtime contains the action costs nothing when a text check misses. A cell
where only a text check stands is where an evasion is a real escape. A cell
where nothing stands is open even to the plain form. Fixing the comment and
string stripper one bug at a time (#294, #295, interpolation) does not say
which of these a given bug sits in. This map does.

## Method

Every verdict comes from **observing the action**, never from an exit code:

| action | the block tries to | observed by |
|---|---|---|
| exec  | start a child process (`touch <marker>`) | the marker file exists |
| read  | read `vault/secret.txt` (`vault/` is in `blocked_paths`) | a random token from that file appears in the program's output |
| write | write `vault/w.txt` | the file exists |
| net   | connect to a local TCP listener (`network.enabled: false`) | the listener accepted a connection |
| env   | read `NAAB_PM_SECRET` (in `env_vars.blocked_read`) | the variable's random token appears in the output |

The tokens are random per probe and never appear in the source, so a token in
the output can only come from performing the action. Each snippet uses the
language's ordinary API: the form a text check is written for, not an evasion.

Each probe runs three times:

1. **control**: audit mode, `unrestricted`, no policy and no rules. The action
   MUST happen here. If it doesn't, the snippet does not do what it claims and
   no verdict is drawn (UNMEASURABLE), or the runtime has no such API by design
   (NO_API, declared per runtime and still required to fail its control).
2. **runtime**: audit mode, at the column's level and policy. Audit mode turns
   every text check into a log line but keeps the sandbox, so this measures the
   runtime alone.
3. **text**: enforce mode, same column: runtime plus text checks. When enforce
   stops an action the runtime let through, the cell is called TEXT only if
   `naab-gov check` (static analysis only, never runs code) blocks the same
   code under the same config. Audit mode also silences runtime gates routed
   through `enforce()`, so this keeps such a gate from being credited to a text
   check.

Columns are a sandbox level plus a policy profile. Every column's policy
forbids all five actions, except that the `shell` profile enables
`capabilities.shell`. Subprocess languages need that to run at all, so exec is
**permitted** there and not probed.

Verdicts: **runtime**: the action is stopped while the language runs.
**refused**: the language does not run at all in this column (also
CONTAINED). **TEXT**: only a text check stops the plain form. **OPEN**:
nothing stops it. **no-api**: the runtime has no such API.

Regenerate: `python3 tools/protmap/protmap.py --md OUT.md --write-baseline tools/protmap/baseline.json`.
This writes the section for the uid it runs as. Run it once as root and once
as an ordinary user (for example `runuser -u nobody -- env HOME=/tmp/h ...`),
or CI's other job will fail PM-02.
The run takes about 35 s with 8 jobs and is deterministic. Five consecutive runs agreed
cell for cell, after fixing a race where Node's asynchronous connect was cut off at
program exit; see `run_probe`.

## What the map says

Of 323 measured cells as root: 122 contained, 67 no-api, 40 **text-only**,
94 **open** (plus 27 where the policy permits exec). As an ordinary user: 131
contained, 39 text-only, 86 open.

1. **`capabilities.shell.enabled: false` does not stop php, go, cpp or rust.**
   It refuses node, shell and ruby entirely, but the four compiled/subprocess
   languages above still compile and run at every level except `restricted`.
   The executor gate (`LanguageRegistry::getExecutor`) checks only
   `BLOCK_CALL`. The refusals that do happen come from
   `PersistentProcessExecutor` (`persistent_process_executor.cpp:291`, checking
   `allow_exec` and `SYS_EXEC`), the base class that node, shell and ruby
   share. The php, go and rust executors have no such check. C++ has a
   `canExecuteCommand` check (`cpp_executor.cpp:270`), and the block ran
   anyway; why it didn't stop the block is not traced here. The CLAUDE.md note "the containment
   that works is `capabilities.shell.enabled: false`" holds for spawning
   naab-lang from shell/ruby/node, but not for these runtimes.
2. **`blocked_paths` reaches no subprocess language.** Python is held by its
   audit hook, and languages that are refused are held trivially. php, go, cpp
   and rust read and write a blocked path at every level, and so do shell and
   ruby once shell is enabled at `elevated` and above. Every one of those
   cells is **OPEN**: no text check flags a plain `os.ReadFile` /
   `file_get_contents` / `std::ifstream` of the path. Node is TEXT-only
   (`restrictions.imports` on `fs`). This extends CONTRA-013, which already
   says there is no OS-level path enforcement.
3. **`env_vars.blocked_read` never reaches a running block.** It gates NAAb's
   `env` stdlib only. Polyglot children inherit the variable. Python and node
   are held only by broad text rules that happen to match (`code_injection` on
   `import os`, `dangerous_calls` on `process.env`). php, go, cpp, rust, and
   shell/ruby with shell enabled read it with nothing in the way (**OPEN**).
4. **`network.enabled: false`** holds Python at runtime at `standard`/`elevated`
   only (TEXT at `unrestricted`). cpp, rust and php are TEXT-only, and go is
   **OPEN** at every level: its `net.Dial` is matched by no check.
5. **Process spawning with shell disabled**: go, cpp and rust are held at
   runtime up to `elevated` (subprocess containment), and TEXT-only at
   `unrestricted`. php is TEXT-only at every level, which matches the known
   finding that its executor escapes `SubprocessContainment`.
6. **Running as root weakens containment.** `RLIMIT_NPROC=0` is half of the
   fork/exec containment at `standard`, and the kernel does not enforce it for
   root. Run as an ordinary user, go is refused outright at `standard` (its
   runtime cannot create threads), so its read/write/net/env cells there go
   from **OPEN** to contained. php's exec at `standard/deny` goes from TEXT to
   contained. Nothing else changes. Containers commonly run as root, so the
   root tables are the ones a containerised deployment gets.
7. **Contained by construction**: QuickJS (no std/os modules loaded) and SQL
   (the authorizer refuses ATTACH and VACUUM INTO) have no API for any of the
   five actions, and `restricted` refuses every subprocess language.

### What this means for the text-check work

Hardening the text checks (reading the raw text as well as the stripped text,
handling interpolation) helps only the **TEXT** cells: python env/net, node
fs/net/env with shell enabled, php exec/net, cpp/rust net, and go/cpp/rust exec
at `unrestricted`. It does nothing for the 94 **OPEN** cells, which a plain
call already passes. Those need runtime enforcement (finding 1 is the cheapest:
gate the executors that spawn on `SYS_EXEC`) or, where no runtime layer is
possible without OS support, new checks with a stated limit.

## Limits

- Linux only. The containment being mapped is the POSIX implementation. The
  suite reports UNMEASURABLE elsewhere.
- Five registered runtimes have no probes: csharp, julia, nim, typescript and
  zig had no toolchain where the map was built (`tools/protmap/unprobed.txt`,
  enforced by PM-01). Their rows are unknown, not safe.
- Each action is probed in ONE ordinary form per language. TEXT means a text
  check stops *that* form. It is not evidence that other forms of the same
  action are caught.
- The text checks are the langconform all-on rule set (`restrictions` and
  `languages.per_language` from `tools/langconform/config.json`). A project
  with fewer rules enabled has fewer TEXT cells and more OPEN ones.
