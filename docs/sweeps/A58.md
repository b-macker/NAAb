# A58 sweep: governance code no test executes

The record for `docs/open-investigations.md` A58. **All 47 classified** (18 in the first pass, 21 in the second, 8 already on record or superseded); the actions they propose are open.

**The run.** `codemap coverage run --name sweep --jobs 4` against `build-cov` rebuilt at `18039b76` (master `dd7744fd` plus docs and tooling only), 2026-10-21: complete -- 290 units wrote counters, every listed unit (321) ran: 318 PASS, 2 FAIL, 1 TIMEOUT (`test_langconform.sh`, at its 600 s bound, so its killed processes wrote nothing). The FAILs: `test_runtime_pin_engines.sh` RP-09/csharp, the known redaction of mcs's version as an IP address (fails on the normal build too); and `test_codemap_coverage.sh` C-06, an isolation defect in that suite -- its "prefix-less" fixture run inherited the unit's own `GCOV_PREFIX` (reproduced: 30 of 31 with the variable set, 31 of 31 without; fixed in the suite by unsetting it). `untested --under` the six governance files: **47** functions executed by no unit (screened; the earlier `4fc80ddb` run read 51). Line numbers below are at `18039b76`.

**Method per function.** Callers from the index and a grep; the history pass (`codemap history`); then, for anything that guards something, a probe with a positive control: the same call refused by the same rule in a place the suite does test, and a permit config under which it runs. An outcome is *verified* only with a probe; *traced* from reading the code. "Executed by no unit" alone is never a finding: the coverage build instruments only naab-lang and naab-gov (roadmap item 1).

## Findings so far

- **A59, fixed:** a VM `async fn` ran with no VM-side governance (the async VM was given no engine since `4f65b2b0`). Found through `saveCounterState`, the tree-walker's counterpart, which held. Sharing the engine with async fns exposed two concurrency defects, both fixed with it: a racing taint sink check that let concurrent tainted writes through unchecked, and unlocked rate limiters (A59 row).
- **A60, fixed (raise-only, owner's decision 2026-10-22):** with `scoring` and `scoring_calibration` enabled, the governed program can zero its own violations' weight -- through `governance.calibrate` or by writing the calibration file -- and pass the cumulative risk gate.
- **A61, open:** a `<<javascript>>` block inside a VM `async fn` always fails ("JavaScript evaluation failed: Unknown error"), before and after A59's fix. Found while building A59's stress program.
- **A62, fixed:** the C API's single named check (`naab_gov_check()`, what every language binding's `check()` calls) passed code its full scan blocks -- secrets and SQL in string literals, JavaScript module names, sudo inside an exec string, a hardcoded key, preg_replace's `/e` -- because since `321500ec` it stripped string literals before every check. Found through `preprocessCode`.

## Limits of this record

- **Blind spots.** The coverage build instruments only `naab-lang` and `naab-gov`, so code reached only through libnaab, naab-lsp or the GoogleTest unit tests reads "executed by no unit" (roadmap item 1). `test_langconform.sh` was killed at its timeout and wrote no counters. Only functions with ZERO executions were swept: a function some unit enters can still have an untested branch, and that is not in this list. Execution is not verification, for the 2,661 functions the run reads as executed too.
- **Direction of error.** The dangerous direction is calling a gate *working* when the probe reached a different path. So every *working* row names the probe and its positive control, and a row read from code only says *traced*. The findings (A59-A62) are the other direction, a protection missing, so each has a control that the same call is refused where the gate is known to hold.
- **Re-tracings.** One per classification. The 47 is one run. The earlier 51 is a different run at a different commit, not a re-trace of this one.
- **Adversarial pass (2026-10-22, before the first push).** It found four errors in this record and the rows it feeds. The classified/recorded/open counts did not add up to 47 (one lambda listed twice, `setInheritedPressure`'s two definitions counted once, a stem lambda missing). A60 named `tools/langconform` as enabling calibration, but its config disables it. The run facts said "290 units; one timeout", when 321 units ran, 290 wrote counters, and two units failed. One of those failures (C-06, above) was not recorded at all until the run's results were re-read.
