# NAAb Language — Internal Reference

Reference for Claude Code when working on the NAAb language source (this repository).

## Build

```bash
# from the repo root
mkdir -p build && cd build && cmake .. && make naab-lang naab-gov -j4
```

- No build type (default): `cmake ..` sets no `CMAKE_BUILD_TYPE` — no `-g`, no `-O`, and `_FORTIFY_SOURCE=2` is defined because the type is not "Debug". It is NOT a Debug build; ask for one with `-DCMAKE_BUILD_TYPE=Debug`.
- Release: `cmake .. -DCMAKE_BUILD_TYPE=Release`
- After modifying CMakeLists.txt: `cmake ..` again before `make`
- Coverage (measurement only, GCC only, its own directory): `cmake -S . -B build-cov -DNAAB_COVERAGE=ON && make -C build-cov naab-lang naab-gov naab-lsp naab-verify-audit naab_unit_tests naab_governance test_governance_c_api -j4` (the list is `gcovmap.COV_TARGETS`; `codemap status` prints it) -- `--coverage -O0 -g` for `codemap coverage` (Code map, below). naab-lang and naab-gov are linked with `-Wl,--wrap=_exit -Wl,--wrap=_Exit` and `src/testing/coverage_exit.c`, which writes gcov's counters before the real `_exit` (in the starting process only), because a HARD block leaves through `_exit(3)` and gcov writes from an exit handler. Never a build to run for real.

Binary lands at `build/naab-lang`. A second CLI, `naab-gov` (`src/cli/gov_main.cpp`), builds via `make naab-gov` for standalone govern.json work. Build it before running the suite: without it `test_r22_fixes.sh` fails ("naab-gov not built … UNMEASURABLE, not a pass") and several other arms SKIP.

**Python polyglot dependency**: the embedded Python executor requires python3 dev headers AND the `pybind11` module (`python3 -m pip install pybind11`) at cmake time — watch for `✓ pybind11` vs `⚠ pybind11 not found (Python executor disabled)` in the configure output. Without it, `<<python>>` expression blocks fall back to the subprocess executor and evaluate to null (a one-time `[polyglot] Python support not available for expression values` stderr warning fires; `run-all-tests.sh` classifies affected tests as missing-executor XFAILs and the property suite skips invariants 4/5). Fresh containers also need `git submodule update --init` and `libcurl4-openssl-dev` — the SessionStart hook `.claude/hooks/session-start.sh` handles all three (remote containers only), and in every session prints one `codemap status` line (Code map, below).

### Test timing (report-only)

```bash
bash tools/testtiming/run_timed.sh   # = run-all-tests.sh, plus test-timing/timing.{md,json}
```

CI's Build & Test runs the suite through this wrapper. It returns `run-all-tests.sh`'s exit status unchanged; a shim placed ahead of `timeout` on PATH records every suite and `.naab` test start (both are launched through `timeout`), and `report.py` attributes time to top-level calls only — a call inside a suite's time window is that suite's own work. The shim must stay invisible: exit status, stdin and signals pass through, which `tests/self-audit/test_test_timing.sh` checks with controls proving each arm can fail. **Local timings are not CI timings**: a default local build has no `CMAKE_BUILD_TYPE` (unoptimised) while CI builds `Release`, so CPU-heavy suites dominate locally — `test_r22_fixes.sh` took 480 s here against roughly 26 s for its 15 MB scan in CI. ### Parallel runner and the dead-interpreter gate

```bash
python3 tools/testrunner/parallel.py run --jobs 4      # report-only; run-all-tests.sh stays the verdict
python3 tools/testrunner/parallel.py compare A.json B.json
python3 tools/testrunner/dead_gate.py run             # every suite vs an interpreter that does nothing
```

`parallel.py` never keeps its own suite list: it asks `run-all-tests.sh` (`NAAB_TEST_PHASE=shell NAAB_TEST_LIST=FILE` list mode), so a suite is registered in one place only. Each unit gets its own HOME/TMPDIR; units that cannot share the machine (the prescan canaries edit `src/`, libnaab builds in `build/`, wall-clock timeout bounds) run alone in an exclusive lane. Measured 2026-10-02: 4 jobs = 473 s vs 1202 s serial, and every unit's verdict and skip count matched the serial run in plan, shuffled and reversed order (#275). `--unit-env NAME=VALUE` (repeatable) sets a variable in each unit's environment with `{unit}` replaced by the unit's own directory name -- `codemap coverage` gives each unit its own `GCOV_PREFIX` this way (`test_parallel_runner.sh` PR-10/PR-10c). `results.json`'s `mode` records `only` and `naab_phase` -- the run's selection, which `units_listed` (counted after the filter) cannot show -- so `codemap coverage` can tell a whole-suite run from a partial one (PR-11/PR-11c).

**Dead-interpreter gate** (CI job of the same name): `dead_gate.py` swaps `build/naab-lang` in a scratch copy for a script that prints nothing and exits 0. A suite that still passes CLEAN -- no failure, no SKIP/UNMEASURABLE -- cannot tell a working interpreter from a dead one, so the gate fails on it unless `tests/self-audit/dead_interpreter_allowlist.txt` gives a reason (`tool`: tests another binary; `structural`: checks source text; `weak`: runs naab-lang but cannot fail -- needs a positive control and leaves the list when it gets one). **A new suite that fails this gate needs a positive control** -- proof the program ran and produced its expected output -- not an allowlist entry. Do not add an entry without reading the suite. Its first run found two suites that printed FAIL and exited 0 (#276) and seven weak ones, inside a green suite. All seven have since been given positive controls and left the list, and the controls found that two were not merely weak but had never tested their subject: `test_alarm_delivery_rt007.sh` passed on the "no govern.json found" exit (governance is required by default), and `test_queue_cap_async002.sh` on parse errors -- it was hiding a VM segfault (see the handle-table gotcha).

**Protection map** (`tools/protmap/protmap.py`, rendered in `docs/protection-map.md`, pinned by `tests/self-audit/test_protection_map.sh` against `tools/protmap/baseline.json`): for each polyglot language x forbidden action (exec, read/write a `blocked_paths` file, connect with `network.enabled: false`, read a `blocked_read` env var) x sandbox level, which layer stops it -- the runtime, only a text check, or nothing. Every verdict observes the action (a marker file, a random token in the output, a listener accept), and a no-policy control must perform it first or the cell is UNMEASURABLE. Audit mode isolates the runtime; a cell is credited to a text check only if `naab-gov check` (static, never runs code) blocks the same code. Measured 2026-10-08 as root: of 323 cells, 25 are text-only and **55 open**; re-measured 2026-10-09 after `blocked_read` reached child processes, **39 open** as root and 36 as non-root (every OPEN env cell -- php, go, cpp, rust, shell and ruby with shell enabled -- moved to contained; python's and node's stay TEXT, see below). As non-root before that fix, 51 open: `RLIMIT_NPROC` does not bind root, so the baseline keeps a `root` and a `nonroot` section and regenerating needs both -- run the non-root half with root's `PATH` and `RUSTUP_HOME`/`CARGO_HOME` passed through, or `su` resets `PATH`, go and rust do not compile, and 64 cells read UNMEASURABLE. All but four of the TEXT/OPEN cells are in columns where the project ENABLES shell: with shell enabled, `blocked_paths` reaches no subprocess language (`env_vars.blocked_read` now does -- see the child-environment gotcha). Python's and node's env cells still read TEXT although the runtime scrub now withholds the variable from them too: the map credits any cell a static check also blocks to the text check, so an enforce-only runtime gate behind a matching text rule is under-credited. A project that disables shell refuses every separate-process language (the shell-off executor gate, see Gotchas); before that gate php/go/cpp/rust ran with shell disabled and 60 cells were TEXT-only or OPEN. The probes run external commands by ABSOLUTE path (`tool_paths()`): a bare name measures `PATH`, not containment, and read six exec cells as contained before the fix (a bare `touch` fails to resolve under the exec-denied `PATH` restriction while a full path runs) -- `probe_broken()` now reports UNMEASURABLE instead, with `--plant-bare`/`--selftest` as controls. **An absent action is credited as stopped only when the arm's output carries a refusal** (`REFUSALS`: the language gate, the sandbox, embedded Python's path and import hooks, the child-environment scrub, Go's thread failure under `RLIMIT_NPROC`) and the run finished on its own; otherwise the cell is UNMEASURABLE and the comparator fails on it, printing the arm's output (`EVIDENCE` lines). Before, any arm whose action was absent read contained -- a timeout, a crash, a script deleted or swapped by a concurrent block (A63; likely, not confirmed, behind a CI run where one PHP cell read CONTAINED instead of OPEN). `--plant-fail`/`--plant-hang` are its controls (PM-07); D17. Text-check hardening (raw view, interpolation) only helps the TEXT cells -- read the map before choosing between a text fix and a runtime one.

**Live-model instrument** (`tools/llm_bridge/`, findings in `docs/llm-bridge-findings.md`): a loopback Gemini server whose requests are answered by a director (a person, or Claude subagent personas), so `examples/agent_harness` meets real, varied model output instead of `agent_stub.py`'s canned replies. Exploratory and not in CI; each run is archived with a stub fixture that replays deterministically (`run_harness.sh RUN --replay FIXTURE`). Every archived run's outcome re-verified by replay at `050cc9fe`. Its shipped-config runs all ended at audit step 1: the worker spent its 4-call tool budget, the loop exited with no final model turn, the empty reply skipped the output contract, and the harness died on `json.parse("")`. Two of those three items are now decided and built (a final tool-less turn; an empty reply violates the contract), so A1/B1/C1 replay to the same exit through the contract instead -- their fixtures hold no reply for the new call, so what a model does with it is unmeasured until a new bridge run. The harness's own crash on an empty reply is still open.

**Setting liveness** (`tools/testrunner/setting_drop.py`, results in `docs/settings-liveness.md`): does any test notice when a govern.json setting stops working? A TEST build (`cmake -DNAAB_CONFIG_MUTATION=ON`, never a build anyone runs for real) lets `NAAB_DROP_SETTING` remove a setting inside `loadFromJson()`, which every config load passes through; `tests/security/test_setting_drop_compiled_out.sh` checks the hook is absent from the normal build, because in a shipped binary that variable would be a governance bypass. Measured 2026-10-03: of 1,474 template settings, **189 live** (a test notices), 747 survive (loaded, no test notices -- dead, set to default, or untested), **538 untested** (no test loads them). Before calling a setting inert, note **`tests/governance_v4/inert_keys_baseline.txt` lists live settings**: its sweep skips `governance_config.cpp`, which holds real consumers (extends merge, ratchet decisions, telemetry forwarder) -- dropping `meta.inheritance.merge_arrays` fails `test_extends.sh` T18a/T18d (a parent's blocked env var is lost).

## Code map (`tools/codemap`)

A queryable index of the C++ source, so the sweeps the investigation method asks for (who calls this, backward from a sink, where threads start, which classes override what) are one command instead of a grep campaign. Indexing needs the libclang Python bindings (`apt-get install python3-clang`, or `pip install libclang`) and `build/compile_commands.json` (CMake writes it); queries need only python3. The index lives in `.cache/codemap/` (git-ignored, ~270 MB).

**The code map informs; `docs/investigation-method.md` decides.** Its answers are leads -- every edge carries its tier, every answer prints its blind spots, coverage reports execution, never verification -- so a code-map answer can send an investigation somewhere but never closes a gate on its own, and an absence it reports ("0 callers", "executed by NO unit") is the map's absence until a probe confirms it. The investigation-gates skill names the query that fits each gate (history and blast radius before a change; callers, `reach`, `tested` before a claim) and says to refresh a stale map before relying on it, or to do the gate by hand when the map is unavailable or cannot be refreshed in time (a reading from a coverage run the status line flags is not evidence). Nothing runs it automatically: the session-start hook prints `codemap status` -- whether an index exists here and how fresh it is, whether libclang can build or refresh one, which coverage run a read would use and whether it is complete, and, when the index or the coverage is not current, the command that refreshes it (coverage: rebuild `build-cov`, then `coverage run` in the background, 45 minutes or more; given whenever the run is not complete, was recorded at another commit, or has files changed after its build) -- and builds nothing. **Work queued for the map** is a row in `docs/open-investigations.md` (A64: governance code no test executes), and the map's own queue -- ten items, ordered, each with its premise check and done-when -- is `docs/plan-codemap-roadmap.md`; a session learns of both there, not from the status line. The index needs `python3-clang` on the machine; on a cloud environment that is a setup-script package (CI's build-and-test installs it, so `naab-env` reports it MISSING when the script lags).

- **Every edge carries its tier**: `[ast]` a direct call; `[value]` the function is passed as a value (callback, `std::function`), so it may be called from somewhere no syntax tree shows; `[lambda]` a lambda the function defines; `[virtual]` a call through a base method that may land in this override; `[dispatch]` a NAAb name (`naab:io.read_file`, `lang:python`) mapped to C++ by recognising the stdlib `call()` branch and `registerExecutor` shapes (screened); `[thread]` a `std::thread`/`std::async`/pool start (screened); `[member]` the virtual methods of a registered executor class; `[predispatch]` a gate the VM and tree-walker run BEFORE dispatching a NAAb stdlib name (below). **Writes** are a separate index: `[write]` is `=`, `op=`, `++`/`--` (built-in or an overloaded operator, so `std::atomic += n` counts) on a field or non-local variable, `[mutate]` a mutating method on it (`store`, `push_back`, `erase`, ... -- a name list, screened); writes to locals are not recorded. A lambda stored in a variable that HOLDS it (`auto callToolLoopTurn = [&]...`, or a `std::function`) is named after the variable; one passed to a constructor (`std::thread t([..])`) is not. `--json` on every query for jq; output is ASCII.
- **What it cannot see, printed with every answer**: code the preprocessor removes for this build (`#ifdef _WIN32` on Linux); calls through a function pointer except where the function is taken as a value; calls on dependent names inside templates; files the build does not compile (`stats` lists them -- 18 tracked C/C++ files on `92d3f249`, `src/analyzer/performance_optimizer.cpp` among them); and a function DEFINED in more than one file on one USR -- every binary's `main(int, char**)` -- is stored once PER FILE (roadmap item 8; before it, the first definition read was kept and the others' call edges merged into it, so `callees main` merged every binary's calls and `gov_main.cpp`'s `main` had no entry: its coverage position read UNMEASURED). Name one `FILE:NAME` (`src/cli/gov_main.cpp:main`); `callers`/`callees` print each as `FILE:NAME`. A call goes to the definition the calling file's translation unit saw; a call from one that saw only a declaration is an edge to EVERY definition, marked `[ast, ambiguous]`, because which one runs depends on the link, which the index does not know. `stats` lists each (6 at this commit, observed: `main()` in 24 files -- the REPL variants, benchmarks, unit and cross-language test programs -- `main(int, char**)` in 7 -- naab-lang, naab-gov, naab-doc, verify-audit, naab-lsp and two tests -- `makeInt` and `printUsage`, each in two separate programs, and two of NAAb's own). The two NAAb ones were investigated (2026-10-22): `StackFrame::toString` belongs to two DIFFERENT classes of one qualified name, `naab::interpreter::StackFrame` (`interpreter.h` and `src/interpreter/error_context.h`), both compiled into `libnaab_interpreter.a` -- but `error_context.o` is linked into no binary built here (observed with `nm`: no `InterpreterErrorReporter` symbol and exactly one `toString` in naab-lang, naab-gov, naab_unit_tests, naab-lsp and libnaab.a), so it is dead code today, and anything that ever pulls it in fails to link (duplicate symbol) rather than misbehaving; `OrchestraModule` is defined in both `orchestra.h` and `stdlib_new_modules.h`, member for member identical -- no violation today, but an edit to one copy would make it one silently. Neither is decided; both are recorded in `docs/plan-codemap-roadmap.md` item 8. **The pre-dispatch filesystem gate is read, not assumed**: the VM and tree-walker gate a NAAb stdlib call BEFORE dispatching it, outside the stdlib function, from the hand-written allowlist `filesystemAccessMode()`. The extractor reads that allowlist's `if (module == ..) { if (method == ..) return ..; return ..; }` shape and, at merge, adds `[predispatch]` edges to `checkFilesystemAllowed`/`checkPathAccess` for every NAAb name it classifies -- but ONLY after checking from the call graph that every non-test caller of the allowlist also calls both gates; a gate edge is the reassuring direction, so on any doubt nothing is added and `stats` says why (`unverified: ...`, `unrecognised: ...`). On `1125fb33`: applied, 37 names gated (file 24, csv 5, io 4, path 2, env 1, log 1), callers checked `VM::run` and `Interpreter::visit` -- since the VM's gates moved into `VM::stdlibCallGates`, the callers checked are that helper and `Interpreter::visit`. The `http` network gate is a [predispatch] MODULE gate on the same terms (every dispatcher runs it under `module == "http"`), and the detectors a dispatcher runs before the call -- BSD pre-check, taint, rate limits, dangerous-call -- are `[precheck]` edges: printed as context, never a gate (`stats` lists each with its dispatchers; a dispatcher is the function that owns the stdlib route, so a same-file helper it calls there, like `stdlibCallGates`, is credited to it). Which checks exist at all is enumerated, not assumed: see the pre-dispatch gotcha. Other checks are not modelled, so a NAAb name reported as an ungated entry point is still a lead, not a finding -- and many such chains are the engine's own writes: `reach fopen --gate GovernanceEngine::checkPathAccess` lists `agent.send()` through the telemetry writer.
- **`reach` is screened, in the reassuring direction too**: a function counts as gated when it calls a gate, or a **gate wrapper** (a function that calls the gate directly; `--gate-hops`), and the search stops there -- order and conditions are not checked, so a gated function can still reach the sink by another branch (the same query stops at `VM::execute`, which calls the gate somewhere in its body). It lists every gated function so each can be verified, prints the sink's direct call-site count as a control (an answer of 0 is printed as such, not as silence), and refuses a `--gate` that names no symbol. `FILE:NAME` picks one of several same-named symbols (`main`).
- **Measured against the grep sweeps it replaces** (observed, this container, `92d3f249`): `enforce` 186 callers, `ErrorSanitizer::sanitize` 15 (10 inside REST route lambdas), 16 `Executor` subclasses, `checkStringLength` 0 callers -- all equal to the prior counts. clangd 18 was tried first and rejected: its call hierarchy dropped call sites inside lambdas (4 of the 15 `sanitize` sites at the time) and has no outgoing calls. Thread starts: 19 found. A newer PlantUML is a new pin line after the same checks.
- **First use on an open item** (A46): the callers of each provider function set against the callers of `chargeCallBudget()` found that `agent.propose()` charges its calls by hand and never compares them with `max_calls_per_run` (then verified with the stub), and `writers DispatchCounters::total_tokens` / `total_calls` returned exactly the lines A46's hand trace had named (2996/5896; 322/2418/5871) -- line numbers at `92d59c56`, before the A46 fix moved every write into `chargeCallBudget()`/`chargeTokenBudget()`. - **Profiles** (`cgprofile.py`, `flame.py`): `profile` runs any command under valgrind's callgrind (`--separate-callers=N`, `--depth`, default 12) and writes `.cache/codemap/profiles/NAME/` -- `folded.txt` (`a;b;c COST`), `flame.svg` (root at the bottom), `icicle.svg` (root at the top), `summary.txt`, `run.json`. **Cost is Ir, instructions executed, not time**: deterministic run to run, blind to I/O and waiting; a stack deeper than N is cut and drawn under `[truncated]`; frames narrower than 0.3 px are not drawn (the subtitle counts them -- `flame --focus FN` re-roots on the stacks through one function). The SVG writer is in the repo, nothing is downloaded. `--run NAME` on `callers`/`callees` marks every static edge `ran Nx` / `not on this edge` (the function ran, never through this call) / `not run` / `unmeasured`, and adds calls only the run saw (`observed Nx`, `via library frames` when std::function or a thread trampoline sat between); a count is that edge's total over the WHOLE run, not along the printed path.

## Key Architecture

### NaabVal (NaN-boxed values)
- `include/naab/naab_val.h` + `src/interpreter/naab_val.cpp`
- 8-byte inline values for int, double, bool, null
- Factory: `NaabVal::makeInt(42)`, `NaabVal::makeString("hi")`, `NaabVal::makeBool(true)`
- Type check: `val.isInt()`, `val.isString()`, `val.isBool()`, `val.isNull()`
- Extract: `val.asInt()`, `val.asString()`, `val.asBool()`
- Bridge: `NaabVal::fromLegacy(shared_ptr<Value>)`, `val.toLegacy()`
- Null check: `val.isNull()` — NOT `if (val)`

### Interpreter
- `src/interpreter/interpreter.cpp` — main visitor
- `src/interpreter/call_dispatch.cpp` — function call routing
- `src/interpreter/expressions.cpp` — expression evaluation
- `result_` (NaabVal) — last evaluated value
- `current_env_` — current scope (shared_ptr\<Environment>)
- `global_env_` — global scope
- `current_file_` — current source file (NOT `filename_`)
- Control flow: `returning_`, `breaking_`, `loop_depth_`
- Environment class: `class Environment` in `include/naab/interpreter.h` (~line 413)

### Bytecode VM
- `include/naab/vm.h` + `src/vm/vm.cpp` — stack-based dispatch
- `include/naab/compiler.h` + `src/vm/compiler.cpp` — AST to bytecode
- VM is default engine (`global_use_vm = true`), tree-walker via `--tree-walk`, which is refused (exit 4) under enforce -- see the engine-under-enforce gotcha
- Computed goto dispatch on GCC/Clang, switch fallback elsewhere
- VM taint tracking: `taint_stack_` mirrors value stack

### Governance Engine
- `src/runtime/governance_engine.cpp` — main engine, signature verification
- `src/runtime/governance_checks.cpp` — 50+ individual checks
- `src/runtime/governance_config.cpp` — config loading from govern.json
- `src/interpreter/governance_taint.cpp` — taint tracking (tree-walker path; the VM carries taint on `taint_stack_` in `vm.cpp`). The two are independent implementations and must agree — `tests/governance_v4/test_taint_engine_parity.sh` is the only thing that checks it. `tests/differential/` cannot: taint is off there because the corpus runs from its own directory and discovery finds `tests/govern.json`, which is `mode: off` (`diff_runner.py`'s `--no-governance` no longer disables a discovered config, #244) — change that file's mode and taint turns on in the differential suite. `expressionContainsTaint()` walks the AST and returns **false for any node type it does not handle**, so a new value-producing `Expr` subclass silently launders taint until added. Violations print in TWO formats — `checkTaintedSink()` (named variable, rule `taint_tracking.sink_violation`) and `checkExpressionTaintedSink()`'s expression path (`Taint tracking violation: expression contains untrusted data...`) — grepping for only one makes a working engine look broken.
- `src/runtime/trust_store.cpp` — Ed25519 trusted key management
- `src/runtime/crypto_utils.cpp` — Ed25519 sign/verify, SHA-256
- Behavioral contracts: `must_call` (function must call specified functions — regex `\bname\s*\(` on body text, non-transitive), `must_contain` (function body must match syntax patterns), `must_produce` (golden tests with type-strict comparison — string "0" does not match int 0), `min_arity`/`max_arity` (parameter count enforcement)
- Anti-gaming: magic number / hardcoded constant detection in polyglot blocks, oversimplification checks, complexity floor
- **Module governance: an imported module gets the entry file's content checks, not its heuristics.** Both engines run `checkNaabSourceText()` (secrets, PII, incomplete logic over the whole text) on the entry file and on every imported module -- VM: `main.cpp` and `Compiler::compileModule()`; tree-walker: `visit(Program)` -- and a module's function bodies go through `checkNaabFunctionBody(..., imported_module=true)`: placeholders, incomplete logic, secrets, PII and the contract run; oversimplification, complexity floor, cosmetic sanitizer, the grouped DX advisories and plugin rules do not. Until 2026-10-09 a module got the contract only, and the tree-walker ran no whole-source check even on the entry file, so a top-level `export let` holding a secret ran there and blocked on the VM. The history is why this is a fix and not a reversal of policy: `247e229d` (EVA-8, anti-evasion) widened the body scan to all functions so code could not route around it; `f9dd7e2c`, a module-import PERFORMANCE fix the next day, skipped module bodies "to avoid unnecessary overhead" and reopened exactly that route; `3e7c94e1`/`ae4bfb67` copied the skip to the VM and named the heuristics as what to keep skipped; `test_module_governance_parity.sh` Group A pinned the result for parity. No commit gave a reason for skipping secrets, PII, placeholders or incomplete logic.   The load-bearing pair from the first campaign: **trace to the point of EFFECT, not the point of mention** (a reference proves nothing — check alias, indirection, reachability and namesakes), and **a negative result without a positive control is not a result**. Plus **a pattern is a hypothesis, not an explanation**, and the **stopping rule** — you are done when a further level of tracing changes nothing, not when you have an answer.

  The second campaign added rules for a failure the tracing rules do not catch: **measuring your own harness and reporting it as the system**. Almost none of those errors were caught by a failing test — the suite was green through every one — and they were not reasoning errors so much as provenance errors. The additions:
  - **Name the provenance of every number** — observed / configured / authored — and say which in the sentence. When you build the fixture, harness, analyzer AND the conclusion, nothing independent can contradict you.
  - **A disabled compensator looks like a broken component.** Calibration was present, working and OFF; its absence made the signals it calibrates look defective, and every measurement agreed. Enumerate what compensates a component and check each is live in the run you measured.
  - **Isolation can remove the property under test.** A per-arm harness gave every arm its own baseline, so the adaptive mechanism could never engage — rigorous-looking and structurally unable to answer.
  - **A sweep over explicit values cannot see a default.** "Key absent" is a distinct condition from "key set false", and it is the one real configs are in.
  - **The shape of the report bounds the finding.** Two premises reported "inert" by a scalar verdict were decisive the moment the same runs were reported as a table of outcomes.
  - **A broken probe reports a finding, not an error.** When the instrument fails, the failure surfaces as a value in the column a real finding goes in — `git ls-files` not invokable on a runner rendered as "88 untracked suites"; a ledger `.txt` matching the candidate-test glob rendered as a PROTECTED gate; a CR renderer piped through a tool that strips CRs rendered as "no CR present". Give every probe a usability check separate from its result and a third outcome (UNMEASURABLE), because two-valued reporting redistributes "did not run" into PASS or FAIL.
  - **Empty output is not a negative result**; **do not mutate what you are observing** (editing a running script, concurrent suites over one build dir); **a new test that passes first try is suspect**; **a confident comment is not a verified one** — the costliest error was a fluent config comment arguing backwards for disabling the mechanism under test.
  - **Unmeasurable is not absent**, and **your own prior conclusions are the least trustworthy input you have** — external claims get checked, your own get inherited.

### Enterprise Readiness
- **Polyglot reload**: both engines call `reloadIfChanged()` before every polyglot block (`f229dd9b`), so a tightening reload applies to the next block; a persistent shell/node/ruby child whose environment policy changed is restarted first (see the child-environment gotcha).
- **Telemetry forwarding**: webhook forwarding of JSONL telemetry events (a SIEM is the same webhook). Keys sit FLAT under `telemetry`: `webhook_url`, `webhook_auth_header`, `webhook_auth_env`, `forward_batch_size`, `forward_timeout_ms`, `forward_retry_count`, `forward_buffer_max`, `forward_shutdown_drain_ms`. The `RunStart`/`RunEnd` anchors are written to the file but never enqueued for forwarding, and the forwarder's final drain runs from `~GovernanceEngine()`, which the CLI's `_exit()` skips — so the forwarded stream cannot settle a missing `RunEnd`.

Parent must pass signature verification.

### MCP server (`naab-lang mcp`)
- Governed execution over the Model Context Protocol, stdio (`src/api/mcp_server.cpp`; design, measurements and withdrawn premises in `docs/plan-mcp-service.md`). Tools: `naab_lease`, `naab_propose`, `naab_commit`, `naab_run`, `naab_verify_attestation`. Protocol revisions 2025-11-25 (`initialize`) and 2026-07-28 (stateless, `server/discover`, per-request `_meta`, `resultType`) are both served.
- **No user code runs in the server process.** Every propose (`run --lint-only`) and commit runs in a fresh `naab-lang run` worker in its own process group, so interpreter state, data and crashes do not cross calls; anything left in the group is killed when the worker exits. The REST server's in-process design leaked Python and shell state between requests and died with one request's segfault (measured); REST `/execute` now uses the same worker (`src/api/worker.h`) -- do not move execution back in-process.
- **Cross-call sequence detection** is a per-caller ledger: workers stream every behavioural-sequence event they record (both `recordEvent()` sites in the engine, including the step `checkPreExecution()` refuses) to an inherited pipe (`--event-stream-fd`), and the next worker replays them with their ages (`--event-seed`) before the program runs. A match completed during replay is NOT enforced -- it was charged in the call that produced it. Replayed events carry turn 0, so only time decay applies. Commits from one caller run one at a time, in arrival order (tickets), while `behavioral_sequences.enabled`; without that, two commits seeded before each other's events could split a sequence past the ledger. Cross-call detection is exactly as strong as the project's BSD config: off by default, and built-in patterns observe-only unless `default_pattern_enforcement: "declared"`.
- **Leases narrow twice**: `enforceMinimumLevels()` applies the grant to the capability switches on every load and reload path (so it reaches the sandbox, and the ratchet compares two narrowed rule sets -- a missing `SHELL_EXEC` refuses every separate-process language through the shell-off gate, but a missing `FS_*` or `NET_CONNECT` reaches only the stdlib and embedded Python, not a subprocess language, CONTRA-013: they bind against polyglot code only with `SHELL_EXEC` withheld too), and `checkFunctionCapability()` intersects it before its empty-map return (the only layer that can express "no `AGENT_SEND`"). **ENV_READ is the exception that needed extra work**: `env_vars.read = false` only gates `env.get()`, so a denied ENV_READ left embedded Python's `os.environ` and child processes reading the caller's environment (found by an external review of #307). `applyLeaseGrantToRules()` now also forces `subprocess_scrub_mode = "allowlist"` with an empty allowed list when ENV_READ is denied, which scrubs every non-essential var from children and `os.environ` (the essential-vars allowlist keeps the worker runnable). Two further in-worker routes read the value past that scrub and are now closed (A32): the process environment FILE (`/proc/<id>/environ`) handed the whole block back as file bytes to `file.read`/`io.read_file`/`env.load_dotenv`/embedded Python `open()`, and the scrub's own `_naab_saved_env` save dict handed the values back to a `<<python>>` block. The filesystem gate now refuses a read of the environ file whenever an env-read restriction is in force (`isProcessEnvironPath()`, one check in `checkPathAccessImpl()`, the shared decision point), and the save dict is held C-side during user code (`SavedEnvHider`). **Still open, the documented `elevated` limit**: a subprocess language (`<<sh>>` reading `/proc/$PPID/environ`) reaches the file -- path policy does not reach a separate process (CONTRA-013) -- closed by `capabilities.shell.enabled:false` or a lease without `SHELL_EXEC`; and `gc.get_objects()` from embedded Python can still reach the save-dict object. These are the general `env_vars.blocked_read` exposure (the file route and `_naab_saved_env` came with #302's scrub), not MCP-specific; see `docs/open-investigations.md` A32. Test: `tests/security/test_env_file_bypass.sh`. `--lease-grant`, `--event-seed`, `--event-stream-fd` are worker plumbing passed only by the server; each can only tighten, and each refuses the run (exit 4) when malformed rather than running with less.
- Output is a new egress (it reaches a model provider through the caller), so the server runs `checkSecrets()`/`checkPii()` under `code_quality.no_secrets`/`no_pii` on BOTH channels and withholds on a hit: stdout (`w.out`) AND the worker's stderr, which is carried back in the `findings` array (the stderr half was missed in the first build and caught by the #307 review — `io.write_error` or a polyglot exception reached the caller verbatim while the same value on stdout was withheld). `audit.provenance.signing_key` is a protected path, but path policy does not reach subprocess languages, so a `<<sh>>` block in a shell-enabled signing project can still read the key (CONTRA-013) — a SHELL_EXEC-less lease or `shell.enabled: false` closes it, the general fix is phase-3 sandboxing; every route to the key is measured in the A32 follow-up, not in #307. The one new key is `api.max_concurrent` (worker processes at once, 0 = CPU cores).
- A loopback HTTP stub cannot observe a send: the http module refuses private and loopback addresses unconditionally (SSRF). The test's sequence ends in a local `file.write` instead.

1. Add implementation in `src/stdlib/<module>_impl.cpp`

## Gotchas

- **`break`/`continue` out of a `try` must close its handler** — `Compiler::visit(BreakStmt)`/`visit(ContinueStmt)` call `emitTryEndsForLoopExit()`, which emits one `OP_TRY_END` per try opened INSIDE the innermost loop (bounded by `loops.back().scope_depth`, the same bound `OP_POPN` uses for locals). Tracked in `CompilerState::open_try_depths`, pushed at `OP_TRY_BEGIN` and popped before `OP_TRY_END` — so a `break` inside a CATCH block emits nothing for that try, whose handler is already gone on both paths. Closing a handler that ENCLOSES the loop is worse than the leak: it delivers a later exception to the wrong catch block. `return` out of a try needs no compiler support — both `OP_RETURN` paths clean handlers by `frame_index` at runtime. Test: `tests/vm/test_try_handler_leak.sh` (tree-walker is the oracle).
- **A VM callback runs in a NESTED `run()`, and only handlers that invocation pushed may catch inside it.** Every native-to-NAAb call (sort comparators, `for_each`/`find`, `array.map_fn`, agent tools, contract golden tests) goes through `VM::callNaabFunction()`, with the native caller on the C++ stack between the callback and its caller's frames. `run()` records `handler_floor` at entry; a throw with no handler above it leaves `run()` as `VMThrownValue` (value + taint), the `run()` that owns the handler delivers it, and `callNaabFunction()` restores frames, handlers, stack, stop level, depth and taint on the way out. Before this (A41) a callback's throw jumped into the caller's catch block from inside the callback's dispatch loop, and the VM was left out of step for whatever ran next. A native caller that catches a callback's exception must keep it (`std::exception_ptr`, rethrown after) rather than replace it -- the array module's sort replaced it, which made a HARD block inside a comparator catchable. Test: `tests/vm/test_callback_throw.sh`.

- **A child process's environment is built in the PARENT, by one function, from the thread's engine -- `buildChildEnvironment()` + `execCandidates()` in `subprocess_helpers.cpp`.** Three defects lived in the old split, and the history explains them: `e1693e97` gave the spawn helper two paths, `execvp()` with the inherited environment or `execve()` with a prebuilt envp when a custom env was passed; `883a06c1` routed EVERY spawn through the second whenever a scrub key (`blocked_subprocess_vars` etc.) was set; `a6ee0a88` then added the containment layers that edit the environment (L1 PATH, L5 proxies, L6 LD_LIBRARY_PATH) as `setenv()`/`unsetenv()` calls in the child.
