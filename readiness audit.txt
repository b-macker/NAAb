
  ---
  NAAb Enterprise Readiness Audit

  Executive Summary

  96K lines of C++ source, 744 test files, 8 CI workflows, 16 stdlib modules, 12 polyglot
  executors, bytecode VM with NaN-boxing. The project is a strong working concept with
  serious governance features. Below are the gaps that separate it from enterprise-ready.

  ---
  TIER 1: Blockers (must fix for any enterprise adoption)

  1.1 No File Stdlib Security (CRITICAL)

  src/stdlib/file_impl.cpp has zero path validation. No realpath(), no traversal checks,
  no allowlist. A NAAb script can file.read("/etc/passwd") regardless of sandbox level.
  The sandbox (src/runtime/sandbox.cpp, 431 lines) checks flags but the file stdlib
  bypasses it entirely.

  Fix: Add path canonicalization + sandbox check to every file operation. The governance
  engine already has checkPathAccess() — wire it into the stdlib.

  1.2 Command Injection in Polyglot Executors (CRITICAL)

  - cpp_executor.cpp:263 — calls system(full_command.c_str()) with constructed strings
  - shell_executor.cpp — uses popen() with user-controlled code
  - generic_subprocess_executor.cpp — same pattern
  - subprocess_helpers.cpp:125-126 — temp file names using mkstemp but the paths pass
  through shell

  The polyglot design inherently executes arbitrary code in foreign runtimes. The sandbox
  flags exist but aren't enforced at the executor level — they're checked in governance
  before execution, which means bypass = full access.

  Fix: Defense in depth — executors should independently verify sandbox permissions, not
  just rely on governance pre-checks.

  1.3 No install Target (HIGH)

  CMakeLists.txt only installs naab-lsp (line 803). There's no install(TARGETS naab-lang
  ...). No pkg-config file. No CMake export config. Enterprises can't integrate NAAb into
  their build systems.

  Fix: Add proper install targets, versioned headers, and a naab-lang-config.cmake.

  1.4 Version Mismatch

  config.h says 0.5.0 but CHANGELOG says 0.7.0. Version string is out of sync.

  Fix: Single source of truth — generate from CMakeLists.txt or git tags.

  2.2 No Unit Test Framework

  tests/unit/ has 41 files but they use the ad-hoc [passed, total] pattern. No test
  runner, no assertions beyond manual comparison, no test discovery. Enterprises need:
  - Proper test assertion functions with diffs
  - Test discovery and selective execution
  - Coverage reporting
  - JUnit/TAP output for CI integration

  2.3 Governance.cpp is 7,484 Lines

  This single file is a maintenance and auditability nightmare. It should be split into:
  - governance_engine.cpp (core load/enforce/report)
  - governance_checks.cpp (the 30+ check functions)
  - governance_security.cpp (taint, secrets, injection checks)
  - governance_reports.cpp (JSON/SARIF/JUnit/CSV/HTML output)
  - governance_audit.cpp (audit trail, telemetry)

  2.4 No LSP Implementation

  tests/lsp/ exists (2 files), CMakeLists.txt builds naab-lsp, but there's no evidence of
  actual language server features (completion, diagnostics, hover). IDE support is
  essential for enterprise developer productivity.

  2.5 GC Relies on shared_ptr Cycle Detection

  46 shared_ptr in interpreter.h, zero weak_ptr anywhere. The cycle detector
  (cycle_detector.cpp) runs periodically but this is fragile. Any environment cycle leaks
  until GC triggers. For long-running processes (servers, daemons), this is a memory leak
  risk.

  2.6 No Async/Concurrent Primitives

  AwaitExpr and YieldExpr exist in the AST but generators are eager-collected (CLAUDE.md
  gotcha #35). No event loop, no promises, no channels. Enterprise workloads need
  non-blocking I/O.

  The REPL exists but lacks readline-style history, tab completion, or multiline editing.

  3.5 Documentation Gaps

  - docs/book/ has 16 chapters — good

  3.6 No Stable Public C/C++ API

  96 headers in include/naab/ with no distinction between public and internal. Enterprises
   embedding NAAb need a stable, versioned API surface with backward compatibility
  guarantees.

  3.7 Error Swallowing

  - governance.cpp audit trail writes: catch (...) {} (line ~5363)
  - governance_init.cpp:54 — catch (...) {} swallows governance init errors
  - These silently drop errors that could indicate corruption

  3.8 No Windows Support

  Build system and executors are Linux/macOS only (popen, mkstemp, flock, localtime_r,
  setenv). No Windows CI. Many enterprises are Windows-first.

  TIER 4: Competitive Differentiators (add real enterprise value)

  4.1 Embeddable Runtime

  Package NAAb as a library (libnaab.so/a) with a C API for embedding in existing
  applications. This is how Lua, mruby, and QuickJS gained enterprise traction.

  4.2 Language Server Protocol

  A working LSP with completions, diagnostics, go-to-definition, and hover would
  dramatically increase adoption. The governance engine could provide real-time rule
  violation diagnostics.

  4.3 Package Registry

  Package manager exists but there's no hosted registry. Enterprise teams need private
  registries, SLA-backed availability, and vulnerability scanning.

  4.4 Governance as a Service

  The governance engine is NAAb's killer feature. Spin it out as a standalone tool that
  can lint polyglot projects (not just NAAb). SARIF output already works — integrate with
  GitHub Code Scanning, GitLab SAST, etc.

  4.5 Deterministic Builds / Reproducibility

  For compliance-heavy industries (finance, healthcare), NAAb scripts should produce
  identical results across runs. Pin polyglot runtime versions, hash dependencies, and
  provide a lockfile mechanism.
